公式：`FIRE 目标 = (月开销 − 兼职净收入) × 12 ÷ 提取率`，`完成度 = 当前资产 ÷ FIRE 目标`。

月开销不是拍出来的，由 [`config.yaml`](config.yaml) 的 `life_plan` 逐项相加得到，每项都标了依据。改一项，目标自动重算。公式的代码落点、校验规则与「为什么这么算」见 [实现方案 §1](docs/DESIGN.md)。

兼职净收入对应咖啡师 FIRE（`fire.labor_income`）：FIRE 后继续做低压力、随时能停的兼职，收入抵掉一部分开销，资产就不必覆盖全部。只扣上班多出来的成本（通勤、在外吃饭的差价、装备摊销）。把 `enabled` 改成 `false` 就退回传统 FIRE（目标 ¥407,720.93），两种口径随时可比。

## 两段式路线

上面的 FIRE 目标是**永续**口径——假设兼职一直做下去、资产永不耗尽。但实际计划是**两段式**的：

| | 阶段 A | 阶段 B |
| --- | --- | --- |
| 地点 | 牡丹江 | 北京 |
| 性质 | 一个人独立生活 | 回归家庭，看护长辈 |
| 收入 | 咖啡师式兼职（¥15–17/时） | 无 |
| 支出来源 | 兼职收入 + 本金消耗 | 家庭共同资金 |
| 退出条件 | 长辈病情加重 → 回京，此后不再回来 | 长辈离世 → 继承 → 在北京生活 |

阶段 A **有明确的退出条件，所以不需要永续**。按年金现值算，2029-06 毕业时约 **¥9.4 万**本金：

| 方案 | 净支出 | 可支撑年数 | 结束年龄 |
| --- | ---: | ---: | ---: |
| 每周 3 天 × ¥15（当前口径） | ¥738/月 | **14.5 年** | 36.5 岁 |
| 每周 4 天 × ¥17 | ¥348/月 | **81.7 年** | 103.7 岁 |

**3 天只够撑 14.5 年，4 天覆盖所有可能长度。** 分界线是外公 92 岁——而这件事无法提前知道。

临界收益率（永续所需的最低实际收益率）：3 天 × ¥15 需 **8.86%**（高于标普500 长期实际回报 6.75%，那是在赌），4 天 × ¥17 只需 **4.18%**（低于提取率，保守假设下自动成立）。

完整推演见 **[docs/FIRE-ROADMAP.md](docs/FIRE-ROADMAP.md)**：时间线、阶段 A 长度敏感性、兼职方案对比与排除项、家庭资源定位。

> ⚠️ 这一段**不改变**上面的 FIRE 目标与完成度。它回答的是另一个问题：这笔钱够不够撑到该回去的那天。

## 计入范围

- ✅ [0.1BTC](https://github.com/SayangChun/0.1BTC) 仓库中的比特币持仓
- ✅ [sp500-dca](https://github.com/SayangChun/sp500-dca) 仓库中的标普500基金市值
- ✅ 纳指100 场外基金（018043 / 160213 / 040046）：份额写在 `config.yaml` 的 `sources.ndx100`，净值抓东方财富公开接口
- ❌ 日常现金、活期存款、其他币种、其他一切资产

划线标准是「长期不动用」，不是「能不能变现」。日常现金要随时周转，所以不算。这条标准的来由、以及历史上哪些资产被纳入又移出（应急金、纳指100），见 [实现方案 §1.4](docs/DESIGN.md)。

> ⚠️ **配置仍然偏斜**：比特币占**七成以上**，而真正「稳」的标普500 只有**四个百分点**——
> 具体数字见上方自动生成的「资产构成」表。
> 「非比特币敞口」虽然已经到四分之一，但其中大部分是纳指——**纳指不算「稳」**：
> 它和标普500 相关性 0.9 以上，都是美股成长敞口，只是纳指更偏科技、波动更大。
> 而 `asset_allocation.sp500_target_range` 的目标是 25–30%，缺口主要在这里。
> 占比由 config 控制，**只做展示，不影响目标**。再平衡路径见 [docs/FIRE-ROADMAP.md](docs/FIRE-ROADMAP.md) §2.3。

推论：卖出资产不会让进度失真，卖出后钱离开这个范围才会。

| 情形 | 进度 | 是否真实 |
| --- | --- | --- |
| 工资入金 / 买入 | ↑ | 真实增长 |
| 池内互换（卖 BTC 买标普500） | → 不变 | 正常 |
| 卖出后把钱花掉 | ↓ | 真实减少 |
| 卖出后变成现金放着 | ↓ | 假信号：资产没少，只是换了形式 |

> 进度跌了，先看钱去哪了。变成现金的话，那是口径边界，不是资产减少。

>
> 月开销是目标的分母，没法全自动。物价会变（取暖费、房租、保费每年都可能调），建议每年 9–10 月复核一次 `life_plan`，跑一遍 `python tests/test_life_plan.py` 确认口径没坏。

## 自动化

GitHub Actions 每小时轮询一次：读两个持仓仓库、抓行情和汇率、重算进度、更新本文件。结果没有实质变化就不提交，避免刷屏。

频率定得高，是因为 GitHub 的定时任务常比计划时间晚几小时触发。每小时跑一次，最大滞后约 1 小时。
