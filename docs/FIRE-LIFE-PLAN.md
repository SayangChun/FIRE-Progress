# FIRE 生活规划书

> 这份文档回答四个问题：**FIRE 后在哪生活、住什么样的房子、每天吃什么、不交社保怎么看病**。
> 它的输出是一个可追溯的「月开销」，而这个数字会直接决定 [README](../README.md) 上的 FIRE 目标。
>
> **所有金额都不是手算的**——它们来自 [`config.yaml`](../config.yaml) 的 `life_plan` 段，
> 由 `scripts/lifeplan.py` 汇总。改一项，FIRE 目标自动重算。

### 2.2 牡丹江作为占位城市的情况

**优点**

- 黑龙江东南部的**区域中心城市**，有三级甲等医院（牡丹江医学院附属红旗医院等），
  医疗资源明显强于鹤岗、伊春这类收缩型小城
- **铁路枢纽**：哈牡高铁、牡佳高铁在此交汇，往返哈尔滨约 1.5 小时。
  探亲与出行的便利性远好于鹤岗（鹤岗要先到佳木斯）
- 城市规模与商业配套更完整（市区人口约 90 万），日常生活选择更多
- 有镜泊湖、雪乡等旅游资源，生活丰富度更高

**代价**

- **房价约为鹤岗的 2 倍**（¥4,292 vs ¥2,083/㎡），折算租金约 ¥667 vs ¥511/月
- 按本规划口径，牡丹江方案比鹤岗方案**月开销高 ¥160、FIRE 目标高约 ¥44,651**
  （¥496,744 vs ¥452,093）

### 2.3 其他候选路线的取舍

| 路线 | 代表城市 | 相对牡丹江 | 取舍 |
| --- | --- | --- | --- |
| 最低成本 | 鹤岗、双鸭山、七台河 | 房价约一半、租金约 3/4 | 目标可省约 ¥45,000；代价是医疗与交通资源弱、人口持续流出 |
| 环境优先 | 伊春 | 房价约 1.2 倍 | 森林城市、空气质量最好；但配套更弱、冬季更冷 |
| 省会路线 | 沈阳、长春、哈尔滨 | 房价约 1.8–2 倍 | 医疗教育交通最好；但月开销会到 ¥3,000+，目标接近翻倍 |

> **一句话**：牡丹江处在「成本 / 配套」之间比较均衡的一档。
> 鹤岗最省但配套弱，省会最全但贵一倍。
> **这个取舍最终要靠实地体验决定**（见 §8 风险清单最后一条）。

### 2.4 换城市要改什么

改 `config.yaml` 里这几处即可，其余自动重算：

| 字段 | 怎么重算 |
| --- | --- |
| `city` / `province` | 城市名 |
| `items[rent].monthly` | 新城市「二手房均价 × 年租金回报率 × 面积 ÷ 12」 |
| `items[heating].monthly` | 新城市取暖单价 × **计费口径换算** ÷ 12 |
| `items[food].monthly` | 按城区物价水平调整 |

改完必须跑 `python tests/test_life_plan.py`，确认口径没被改坏。

## 3. 住房选择

### 3.1 租房方案（当前采用）

| 项目 | 金额 | 依据 |
| --- | ---: | --- |
| 房租 | ¥550/月 | 40㎡ 一居室。牡丹江市区均价 ¥4,292/㎡、年租金回报率 3.73%，折算 40㎡ 月租约 ¥534 |
| 取暖费 | ¥75/月 | 居民供热 ¥28/㎡ 按**使用面积**计收（约合建筑面积 80%）：40㎡ × 80% × ¥28 ÷ 12 ≈ ¥75 |
| 物业费 | ¥25/月 | 约 ¥0.6/㎡/月；老小区更低，部分无物业 |
| 水费 | ¥12/月 | 单人约 3 吨 |
| 电费 | ¥55/月 | 约 110 度。冬季靠集中供暖，**不需要电暖器**，用电量远低于南方 |
| 燃气/液化气 | ¥35/月 | 自己做饭；牡丹江管道燃气覆盖较好，可能更低 |
| 家电维修与更换摊销 | ¥20/月 | 改买二手（约 ¥200–300），按 10 年摊销 |

### 3.2 取暖费：东北特有的固定成本

这是北方 FIRE 预算里最容易被南方经验漏掉的一项。它的特点是：

- **不可选、不可省**——冬天不交取暖费就是没暖气，牡丹江冬季最低气温可达 −25 ~ −30℃。
- **按面积收**，所以住得越大越贵，与「极简」的省钱方向天然冲突。
- **按采暖季一次性缴**（通常 9–10 月），不是按月扣。做现金流时要单独留出这笔钱。
- **计费口径各地不同**：牡丹江按使用面积、鹤岗按建筑面积的 87%、
  哈尔滨按建筑面积。同一单价下，实际支出可能差 20%。

> **租房时谁交取暖费，必须在合同里写清楚。**
> 东北的租房市场上两种都有：有的房东包取暖费（租金已含），有的明确「取暖费自理」。
> 本规划按**租客自付**建模——这是保守假设。如果房东包，月开销会低 ¥75。

### 3.3 租房注意事项

- **冬季看房**：一定要在供暖季实地看一次，确认室温与供暖是否达标。夏天看房看不出供暖问题。
- **老小区步梯房**：牡丹江低价房源里 10 年以上房龄的步梯房不少，低楼层/顶楼的采光与保温要重点看。
- **警惕超低价房源**：网上流传的「5 万一套」多在偏远矿区，没公交、没超市、供暖还不好。
  真正能日常居住的，刚需款大致 ¥15 万起。
- **供暖费、物业费、水电燃气由谁承担**——逐项写进合同，别口头约定。

### 3.4 租 vs 买：算一遍

这是本规划里最值得算清楚的一件事，因为结论不直观。

**判据**：把买房看成「花一笔钱，买断未来的房租」。这笔钱的隐含回报率 = `净省下的房租 ÷ 购房投入`。
再拿它和提取率（4.3%）比——高于 4.3% 才说明买房划算。

| 方案 | 月开销 | FIRE 目标 | 一次性支出 | **合计资金需求** |
| --- | ---: | ---: | ---: | ---: |
| 租房（当前） | ¥1,780 | ¥496,744.19 | ¥15,000 | **¥511,744.19** |
| 买房（40㎡ 二手房） | ¥1,330 | ¥371,162.79 | ¥190,680 | **¥561,842.79** |

买房方案的口径（**必须和租房同面积**，否则是苹果比橘子）：
- 房款 ¥171,680（40㎡ × ¥4,292/㎡）+ 契税与过户约 ¥5,000
- 月开销 = ¥1,780 − ¥550（不再付房租）+ ¥100（维修与大修摊销）= ¥1,330
- 一次性支出 = ¥171,680 + ¥5,000 + ¥8,000（家具家电）+ ¥3,000（搬家）+ ¥3,000（过冬装备）= ¥190,680

**隐含净回报率 = (¥6,600 年省租金 − ¥1,200 年维修) ÷ ¥176,680 = 3.06%**

3.06% 比提取率低 1.24 个百分点，**租房明显更划算：买房合计资金需求多约 ¥50,099（9.8%）**。

> ⚠️ **牡丹江的租房优势比鹤岗更明显，原因是「租售比」。**
> 牡丹江年租金回报率 **3.73%**，鹤岗是 **5.88%**（售租比 17）。
> 租售比越低，说明房价相对租金越贵，买断房租就越不划算——
> 所以牡丹江是「租房明显更优」，而鹤岗只是「租房略优」。
> **同一笔钱，在租金回报率高的城市买房更值，在回报率低的城市租房更值。**

**买房还有下面几件事让它更不划算：**

1. **房价下行风险仍在**：牡丹江 2026-08 二手住宅价格指数同比 −2.8%（90㎡ 及以下 −3.1%）。
   跌 20% 本金损失约 ¥34,000，远超买房的账面收益。
2. **流动性差**：东北整体人口流出，房子出手不快。租房可以随时换城市，买房不行。
3. **交易成本**：买入约 3%、卖出再 3%，一进一出约 ¥5,000+，**刚好把这 1.1% 的优势抹平**。
4. **机会成本**：¥176,680 一次性支出后就不再产生现金流。而租房方案里，
   这笔钱是 FIRE 组合的一部分，每年产出约 ¥7,597（按 4.3%）。
5. **本模型没算房价升值**——在人口流出的城市里，长期升值假设本身就不成立。

**结论：按租房建模，而且这不是勉强的选择——牡丹江的租房在财务上明显更优**
（省 ¥50,099 / 9.8%）。叠加「不锁死本金 + 保留换城市的自由」，租房是双重占优。
在资产还只有 ¥14k 的阶段，这个结论尤其牢固。

> **切换方式**：等真到了要做决定的时候，如果房价继续下跌、或你确定要长期安定下来，
> 把 `config.yaml` 里的 `housing` 改成 `buy`、房租项换成维修摊销项，目标会自动重算。
> 注意**两条腿都要动**（去掉房租 + 加上维修），只改一条会得到错误结果。

## 4. 每天饮食安排

### 4.1 原则

1. **早市优先**。东北城市早市菜价比超市低约 30%（鹤岗实测：黄瓜早市 ¥1.5/斤、超市 ¥2.5/斤），
   且早上 6–8 点去最新鲜。这是食品预算能压到 ¥500/月 的关键。
2. **一次多做、分次吃**。炖菜（白菜炖豆腐、土豆炖牛肉、酸菜炖粉条）做一锅吃两天，
   省燃气也省时间。
3. **跟着季节走**。夏天蔬菜便宜，冬天靠囤菜与腌菜。
4. **自己做饭为主，每月留 ¥50 偶尔外食**——极简不等于苦行。

### 4.2 一周食谱（示例）

| | 早餐 | 午餐 | 晚餐 |
| --- | --- | --- | --- |
| 周一 | 小米粥 + 煮蛋 + 酱菜 | 白菜炖豆腐 + 米饭 | 西红柿鸡蛋面 |
| 周二 | 玉米面粥 + 早市包子 | 土豆炖牛肉（一锅） + 米饭 | 剩菜 + 米饭 |
| 周三 | 小米粥 + 煮蛋 | 酸菜炖粉条 + 米饭 | 疙瘩汤 + 拌黄瓜 |
| 周四 | 馒头 + 豆浆 | 地三鲜 + 米饭 | 白菜猪肉饺子（包一次冻起来） |
| 周五 | 小米粥 + 酱菜 | 豆腐炖鱼（冷冻鱼） + 米饭 | 剩饺子煎一下 |
| 周六 | 煮面 + 鸡蛋 | 土豆炖豆角 + 米饭 | 拌菜 + 粥 |

> 东北的饮食结构对低成本 FIRE 是友好的：**炖菜为主**，一锅出、食材便宜（白菜、土豆、
> 粉条、豆腐都是低价高饱腹的东西），不像南方菜系那样依赖大量新鲜细菜。

### 4.4 东北特有的季节性问题：囤冬菜

**10 月下旬**是冬菜上市季，这一个月把冬天的菜买齐，能显著压低 12 月–次年 3 月的食品支出：

- **大白菜**：约 ¥0.4–0.8/kg，买 100 斤（50kg）≈ ¥30，一部分鲜储、一部分腌酸菜
- **土豆、萝卜、大葱**：耐储，成袋买更便宜
- **腌酸菜**：自己腌一缸，冬天炖粉条、包饺子都用得上，成本远低于买成品

> 这一项没有单独建模（已包含在「食品 ¥450」里），但它是东北生活成本能压到这么低的重要原因。
> 不会腌菜也没关系，冬季蔬菜靠外埠调运，价格会季节性上涨——所以 §7 的敏感性分析里
> 把月开销上浮到 ¥2,000 当作一个重要情景。

## 5. 医疗与保障（不交社保的完整路径）

不交社保是本规划里**风险最集中**的一环，需要单独设计。

### 5.1 不交社保意味着什么

| 失去的 | 后果 |
| --- | --- |
| 职工养老保险 | **没有养老金**，FIRE 组合是终身唯一的收入来源 |
| 职工医疗保险 | 报销比例更低、无个人账户、门诊统筹有限 |
| 生育/失业/工伤保险 | 与 FIRE 场景基本无关，可忽略 |

> ⚠️ **这是一个不可逆的决定，值得再确认一次。**
> 职工养老保险需累计缴满 15 年才能在退休后领取。现在不交，等于彻底放弃这条路径。
> 如果将来改变主意，缴费年限要重新起算（除非之前已有缴费记录）。

### 5.2 兜底方案一：城乡居民基本医疗保险

- **费用**：¥400/年（2026 年国家统一标准）= **¥33/月**
- **性质**：这是不交社保后**唯一的基础医保**，必须参保，不能裸奔
- **与职工医保的差距**：住院报销比例通常 50%–70%（职工医保约 80%–90%），
  没有个人账户返钱，门诊待遇也弱
- **结论**：能兜住「不至于因病返贫」，但兜不住「大病自付部分」，所以还需要下面两层

### 5.3 兜底方案二：龙江惠民保（补充医疗）

- **费用**：普惠版 ¥99/年、升级版 ¥150/年 = **约 ¥13/月**
- **特点**：政府指导、**不限年龄、无需健康告知、带病可保可赔**——这对将来年纪大了再投保特别重要
- **作用**：覆盖医保目录外的自费药与高值耗材，正好补上居民医保的短板
- **注意**：免赔额较高（通常万元以上），定位是「防大病」而不是「报小病」。
  每年保费与条款会调整，以当年官方发布为准

### 5.4 兜底方案三：医疗应急金（重要）

4.3% 提取率覆盖的是**日常**开销，覆盖不了「一次性大额医疗支出」。建议单列一笔专项：

- **金额建议**：¥50,000–100,000
- **不参与** `月开销 × 12 ÷ 提取率` 的计算，是独立于 FIRE 目标的一笔钱
- **放在哪**：货币基金 / 短债基金，随时可取，不要放进比特币或权益类
- **为什么必须有**：不交社保意味着没有单位补充医疗、没有工伤兜底，
  所有医疗风险都由自己承担

> 这笔钱**没有计入本文的 FIRE 目标**，所以实际需要的总资产应比 ¥496,744 更高。
> 建议在资产规模接近目标时，把这笔专项金一并纳入规划。

### 5.5 参保地问题（容易被忽略）

城乡居民医保按**户籍地或居住证所在地**参保。异地租房会遇到一个现实问题：

| 情况 | 做法 | 代价 |
| --- | --- | --- |
| 保留原户籍 | 在户籍地参保 | 异地就医需备案，报销比例可能再降 |
| 办牡丹江居住证 | 在牡丹江参保 | 需满足当地居住证办理条件（通常要求稳定住所+居住时间） |
| 落户牡丹江 | 在牡丹江参保 | 牡丹江落户政策较宽松，但**租房落户需按当地政策核实** |

**务实建议**：先保留户籍地参保（最省事、不会断保），到牡丹江稳定居住后办居住证，
再评估是否转移。**不要出现断保**——城乡居民医保断缴后再参保通常有等待期。

### 5.6 值得考虑：城乡居民养老保险

「不交职工社保」不等于「完全没有养老兜底」。**城乡居民养老保险**是一条低成本路径：

- 年缴费可选档次（各地通常 ¥100–3,000 自选），缴满 15 年，60 岁后可领
  「基础养老金 + 个人账户养老金」
- 基础养老金由财政发放，标准各地不同，**具体金额需按参保地政策核实**
- 定位是「聊胜于无的兜底」，不能替代 FIRE 组合，但每年几百块的投入换来一份终身现金流，
  对不交职工社保的人来说性价比不低

> 是否参保由你决定。本文的 FIRE 目标**未包含**这项收入，属于保守处理——
> 如果将来参保并领取，实际需要的资产会比目标更低。

### 5.7 提取率要不要更保守？

**这是一个需要认真对待的问题。** 4.3% 这个提取率，通常建立在「有养老金作为底层现金流」的
假设上。而本规划的前提是**不交社保、没有养老金**：

- 组合是终身唯一收入来源，没有「领完了还有养老金」的兜底
- 医疗支出随年龄上升，而居民医保的报销比例低于职工医保
- 一旦组合大幅回撤且同时需要用钱，没有第二道防线

| 提取率 | 对应 FIRE 目标（月开销 ¥1,780） |
| --- | ---: |
| 3.5% | ¥610,285.71 |
| 4.0% | ¥534,000.00 |
| **4.3%（当前）** | **¥496,744.19** |
| 4.5% | ¥474,666.67 |

从 4.3% 收紧到 4.0%，目标要多约 ¥37,256（+7.5%）；收紧到 3.5%，要多约 ¥113,542（+22.9%）。

**建议**：现阶段保留 4.3%（资产规模还小，先把目标定在可触及的位置），
但在资产接近目标、真正要「按下按钮」之前，**重新评估一次提取率**——
那时才是这个决定真正产生后果的时候。

## 8. 风险清单

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| **不交社保** | 无养老金、医保待遇弱，组合是唯一收入来源 | 城乡居民医保 + 惠民保 + 专项应急金；考虑城乡居民养老保险；临近 FIRE 时重新评估提取率 |
| **大病** | 一次性大额支出，可能击穿 4.3% 提取率 | §5.4 专项应急金（¥50k–100k），独立于 FIRE 目标 |
| **房租上涨** | 每月最贵的一项，涨 10% 就是 +¥52/月 | 长租合同锁定；或届时评估买房（§3.4） |
| **通胀** | 4.3% 提取率已按实际收益率设计，但若通胀长期高于预期，购买力会被侵蚀 | 组合保持权益类占比；每年复核月开销 |
| **城市收缩** | 东北人口持续流出，长期看商业与医疗资源可能收缩，房价承压 | 保留换城市的能力（这正是选择租房而非买房的核心原因） |
| **医保政策变化** | 惠民保等产品每年调整，可能涨价或缩减保障 | 每年复核保费；把它当作可选项而非依赖项 |
| **气候与社交** | 冬季漫长、日照短；从大城市迁入小城可能有社交断层 | 这条不在财务模型里，但对 FIRE 生活质量的影响可能超过钱——**建议先实地过一冬再决定** |
| **目标口径变更** | 本次改动让进度曲线出现台阶 | 已在 §0 说明；`history.json` 每天记录当时的 `target_cny`，可追溯 |

> **最该先做的一件事**：在真正决定定居城市之前，**去候选城市实地住一个冬天**
> （至少 11 月–次年 1 月）。牡丹江的冬天和鹤岗、伊春并不一样。
> 取暖、日照、社交、医疗可及性这些问题，任何数据都替代不了亲身体验。

## 10. 怎么维护这份规划

所有金额都集中在 `config.yaml`，**改一处即可，FIRE 目标会自动重算**：

```yaml
life_plan:
  profile: hegang-rent-minimal   # ← 切换方案只改这一行
  profiles:
    hegang-rent-minimal:
      items:
        - {key: rent, ..., monthly: 520, ...}   # ← 改房租
```

改完必须跑测试（口径错了不会报错，只会让目标悄悄跑偏）：

```bash
python tests/test_life_plan.py    # 生活规划口径（26 项）
python tests/test_commit_gate.py  # 提交门控（14 项）
```

`tests/test_life_plan.py` 钉住了几条关键性质，其中最重要的一条是
**「一次性支出不得摊进月开销」**——这条一旦被改坏，FIRE 目标会被静默虚增。

若只想临时试算「如果每月花 ¥3,000 会怎样」，不必改明细，直接在 `config.yaml` 里填：

```yaml
fire:
  monthly_expense: 3000   # 填数字 = 覆盖 life_plan 的推导结果
```

README 会标注「当前为手工覆盖值」，不会把它误当成正式口径。试算完记得改回 `null`。
